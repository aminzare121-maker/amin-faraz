# موتور مستقل قواعد آرتین — نسخهٔ آفلاین ۰٫۱

این بسته از صفر و جدا از موتورهای قبلی ساخته شده است. import، API، تنظیمات، حساب، دیتافید یا state مشترک با هیچ موتور قبلی ندارد. فقط از Python استاندارد و فایل‌های همین پوشه استفاده می‌کند؛ نصب بسته‌ای لازم نیست.

**قابلیت فعلی:** اجرای ۱۲ شاخهٔ مستند ورود، محاسبهٔ حجم، ثبت fill کاغذی، مدیریت SL، تشخیص رخداد خروج و حسابداری خروج با قواعد ثابت باکس. ورودیِ تشخیص‌هایی مانند پیوت، دوجی، قدرت کندل، PRZ و sentiment باید طبق درس با منبع و زمان معلوم‌شدن ثبت شود. **این نسخه تشخیص خودکار تمام این موارد از چارت/خبر خام یا اتصال بروکر ندارد.** آن را موتور خودکارِ کامل، عیناً تأییدشده در تمام دوره یا سودآور معرفی نمی‌کنیم.

## اجرا

با Python موجود۳٫۱۰ یا جدیدتر، از داخل همین پوشه:

```text
python -B -m unittest discover -v
python -B run_engine.py --demo --output DEMO_RESULT.json
python -B run_engine.py --input MY_OBSERVATIONS.json --output MY_RESULT.json
```

در ویندوز `RUN_DEMO_WINDOWS.bat` هم قابل استفاده است. اگر Python در PATH نیست، مسیر مفسر موجود را در متغیر محلی `ARTIN_PYTHON` مشخص کنید؛ اسکریپت چیزی نصب نمی‌کند. استفاده از مفسر موجودِ یک پوشه، به معنی واردکردن کد یا اتصال به موتور آن پوشه نیست.

ورودی نمونه با این فرمان قابل ذخیره است:

```text
python -B export_example.py
```

تمام قیمت‌ها، ریسک‌ها، قرارداد، هزینه و علامت‌های مثال **کاملاً ساختگی** هستند؛ تنظیمات پیشنهادی مدرس یا Eplanet نیستند. `ELIGIBLE` یعنی شروط روی ورودی‌های اعلام‌شده برقرارند؛ به معنی سفارش، برد یا سود نیست.

## ورودی و خروجی

هر `Fact` مقدار، `known_at` و `source` دارد. زمانِ دانستنِ ورودی نباید بعد از زمان تصمیم باشد. قیمت‌ها و پول با Decimal یا رشتهٔ اعشاری دقیق داده می‌شوند؛ float دودویی در Fact پذیرفته نیست. Engine فقط قاعده‌های مشخص‌شده در plan ثابت را بررسی می‌کند.

در JSON ورودی، `mode` باید ANNOTATED_OFFLINE باشد؛ `plan_id`، `allowed_rules` و `cases` صریح‌اند. هر case شامل rule_id، side، at و facts است. در صورت وجود paper_trade، قرارداد، هزینه، بودجه، تعریف هدفِ باکس، قیمت هدفِ همان معامله، ریسک تجمیعیِ باقی‌مانده و رویدادهای fill_entry/quote/manage/close نیز صریح‌اند. نام رویداد هرگز به shell یا فراخوانی دلخواه تبدیل نمی‌شود.

باکس **قاعدهٔ هدف** را ثابت می‌کند، نه اینکه همهٔ معاملاتِ باکس قیمت هدف یکسان داشته باشند. قیمت هدف و SL اولیهٔ هر معامله از مدل منتخب مدرس به موتور داده می‌شوند. موتور برای یک‌سومِ حد، هدف، RR یا trigger مدیریت عدد اختراعی تعیین نمی‌کند.

## وفاداری‌های رفتاریِ آزموده‌شده

- هم‌رنگ: کلوز مکث خودش، بدون اجبار تأیید اضافه؛ دوجیِ جلو: کلوز دوجی؛ دوجیِ سربه‌سر: کلوز بعدی بالای سایه و نزدیک.
- مخالف‌رنگ با تأیید: بین گره‌های قبلی نیز در شرایط مستند بررسی می‌شود؛ هر مکث به‌تنهایی ورود نیست.
- جلو/سربه‌سر از شمار تحلیل درست/غلط می‌آید؛ PnL جای آن نمی‌نشیند. شاخهٔ آغاز/عقب‌بودن که استخراج نشده، REVIEW است؛ آن را منعِ ادعایی مدرس نمی‌نامیم.
- شکست خیلی‌قوی: تماس نیمهٔ بدنه، بدون اجبار کندل بستهٔ تازه. استثنای fullbodyپس‌پولبک پیش از عبور پیوت حفظ شده است.
- روند قوی، منع جهانی برگشت نیست؛ استثنای PRZ جلسه۱۵ در مسیر مرتبط و ارجاع خروجی باقی است.
- جزئیات فروشِ StopPunch از شکل صعودی خودکار قرینه نشده؛ در نبود نگاشت مستقل REVIEW می‌دهد. این محدودیت استخراج ماست، نه حکم نبود مدل فروش در آموزش.
- Reduce/riskfree/saveprofit حرکت SL با حجم ثابت‌اند؛ پرشدن خروج و سود تحقق‌یافته جعل نمی‌شوند.

## چرخهٔ معامله و ریسک

prepare فقط PAPER_ENTRY_INTENT تولید می‌کند. fill_entry یک fill کاغذیِ صریح ثبت می‌کند؛ fill زیان‌بارِ بیش از بودجه با OPEN_REVIEW ثبت می‌شود، نه اینکه واقعیت آن نادیده گرفته شود. quote در خروج BUY از Bid و در SELL از Ask استفاده می‌کند؛ لمس SL/TP فقط EXIT_TRIGGER است و قیمت fill فرض نمی‌شود.

close با fill نامعلوم، UNKNOWN می‌ماند. اگر خروج معلوم ولی هزینه نامعلوم باشد، وضعیت CLOSED_PENDING_COST است؛ پوزیشن باز فرض نمی‌شود و PnL هنوز نامعلوم است. با رسیدن هزینهٔ واقعیِ اعلام‌شده، حسابداری تکمیل می‌شود. هزینهٔ کامل رفت‌وبرگشت فقط یک‌بار کم می‌شود. allowance در مدل سایز، هزینهٔ تاریخی تأییدشده نیست.

هر نمونهٔ TradeMachine برای یک معامله است؛ این انتخاب یک قانون همیشگی «فقط یک پوزیشن» به مدرس نسبت نمی‌دهد. رزرو و به‌روزرسانی ریسک تجمیعی میان چند نمونه باید توسط مصرف‌کنندهٔ جدید همین بسته انجام شود؛ هیچ حساب یا کنترلر موتور دیگری خوانده نمی‌شود. درخت خودکار برد/باخت، مقدار ریسک/RR تازه یا افزایش خودکار سرمایه پیاده نشده است.

## نتیجهٔ واقعی تحویل

اجرای نهایی یکپارچه:۲۸تست،۲۸PASS،صفرFAIL/ERROR/SKIP.۱۲سناریوی ورودیِ ساختگی نیز اجرا شدند؛ همه با شروط کامل خودشان ELIGIBLE بودند. این شمارها معامله/برد/آزمون بازار نیستند. مرجع عبارات و مثال‌ها مدرس است؛ تشخیص‌های ورودیِ ساختگی فقط ابزار آزمون‌اند و ادراک مدرس را ثابت نمی‌کنند.

هیچ MT5، سفارش، نصب، تغییر ربات قبلی، سرویس، Startup، ارتباط موتور قبلی یا Merge انجام نشده است. برای ادعای انطباق کاملِ خودکار، تشخیص ورودی‌ها باید جداگانه با مثال‌های مدرس تطبیق و آزموده شود؛ این بخش در این نسخه پیاده نشده است.

# اجرای محدود پل ویندوز — Issue38

این پرونده دربارهٔ اجرای یک‌بارهٔ پل و آزمون adapterهاست. نصب، سرویس، Startup، کنترل دسکتاپ، معامله، تغییر ربات، main یا Merge در دامنه نیست.

## نسخهٔ اولیهٔ دقیق

پنج فایل PR39، commit `0acc8c808ae29743de9afb4cc5780f8e3bac78e2`، در یک پوشهٔ جدا دریافت و هر پنج Git blob SHA با remote تطبیق داده شد. اصل این فایل‌ها تغییر نکرده است. Python موجود 3.12.14 است؛ نصب تازه‌ای انجام نشد. آزمون واقعی `python -B -m unittest -v test_bridge_agent.py`: از ۱۳ case، ۱۲ موفق، ۱ ردشده به دلیل عدم امکان ساخت symlink در ویندوز، صفر شکست/خطا. «۱۳ موفق» گزارش نمی‌شود. رسید `BASELINE_RECEIPT.json` شامل هش‌های کامل است.

مالک پوشهٔ آزمایشی جدا و استفاده از احراز هویت محلی ازپیش‌موجود را صریحاً تأیید کرد. این مجوز به کل Documents، اطلاعات حساب یا دادهٔ طلا گسترش نمی‌یابد. `gh` و متغیرهای متداول token در نشست موجود نبودند؛ Git Credential Manager از قبل تنظیم شده بود. وجود helper به‌تنهایی اثبات اعتبار قابل استفاده نیست. مقدار credential در خروجی ابزار، فایل، چت، خط فرمان یا گزارش منتشر نمی‌شود.

## نسخهٔ مستقل و کنترل‌های پیش از اجرای زنده

کد اولیه محفوظ است؛ نسخهٔ محدودتر در `hardened/` و adapterهای آفلاین در `adapters/` قرار دارند. نسخهٔ زنده فقط پاسخ status همان شناسهٔ handshake تعیین‌شده در Issue38 را می‌پذیرد. فرمان‌های عمومی فایل/تست از صف زنده غیرفعال‌اند؛ تست Python در کتابخانه sandbox نیست و فعال‌سازی آن دامنهٔ این اجرا نیست.

کنترل‌های بررسی‌شده باید شامل origin/endpoint/method ثابت GitHub و API version، رد redirect، سقف پاسخ، تفکیک state براساس repo/Issue/workspace، جلوگیری از تکرار شناسه، توقف قابل‌ممیزی پس از crash، کنترل alias/reparse و پیمایش محدود باشند. گزارش نهایی آزمون‌ها و نتیجهٔ واقعی اجرای یک‌باره در رسید جدا ثبت می‌شود؛ صرف ساخت کد، handshake موفق محسوب نمی‌شود.

راه‌انداز محلی `local_once_host.py` از فرمان ثابت Git Credential Manager با prompt و trace غیرفعال استفاده می‌کند؛ stdout/stderr احراز هویت را فقط داخل فرایند می‌گیرد و هرگز بازنشر نمی‌کند. فقط اگر اعتبار موجود فراهم شود، آن را در environment موقت فرزندِ یک‌باره قرار می‌دهد؛ environment سراسری تغییر نمی‌کند. این حافظهٔ Python پاک‌سازی رمزنگارانه را تضمین نمی‌کند. هیچ ورود مرورگری، ذخیرهٔ credential تازه یا استخراج token اتصال GitHub در ChatGPT انجام نمی‌شود. [مستند GCM دربارهٔ غیرفعال‌کردن تعامل](https://github.com/git-ecosystem/git-credential-manager/blob/main/docs/environment.md#gcm_interactive) و [قرارداد git credential](https://git-scm.com/docs/git-credential) مبنای این روش‌اند.

## adapterهای MT5 و ربات

آزمون‌ها فقط با دادهٔ ساختگی و proxy تزریق‌شده انجام شده‌اند؛ نتیجهٔ ساختگی شاهد DEMO واقعی نیست. guardهای handshake و رضایت نشست مشخص، DEMO، Eplanet و نماد دقیق XAUUSD.st باید پیش از دریافت بازار بگذرند. حداکثر ۱۰۰ کندل M15 بسته، ثبت محلی کدهای ثابت، توقف در خرابی audit، و خروجی فقط شمار/وضعیت/خطای ثابت پیش‌بینی شده‌اند. هیچ dispatch آزاد نام API، order_send، order_check، login/relogin یا تنظیمات ترمینال وجود ندارد. APIهای لازم برای سفارش‌ها و پوزیشن‌ها عمداً خوانده نمی‌شوند؛ برای اثبات اتصال نیازی به آن‌ها نیست.

این نسخه هیچ SDK را import یا initialize نکرده است. binding نشست واقعی هنوز متصل نشده و رضایت پوشه، رضایت نشست MT5 محسوب نمی‌شود. طبق [مستند رسمی MetaTrader](https://www.mql5.com/en/docs/python_metatrader5/mt5initialize_py)، initialize ممکن است ترمینال را در صورت نیاز راه‌اندازی کند و از اطلاعات ذخیره‌شدهٔ حساب استفاده کند؛ بنابراین initialize خودکار، انتخاب ترمینال خودکار یا اتصال با رمز ذخیره‌شده به‌عنوان «read-only بی‌اثر» فرض نمی‌شود. اتصال بعدی باید به نشست مشخصِ تأییدشده و موجود محدود بماند.

مشاهدهٔ ربات به مسیر دقیق status تأییدشده و schema شناخته‌شده وابسته است. در نبود آن، وضعیت `unknown / PATH_APPROVAL_REQUIRED` است؛ نام فایل یا فرایند به تنهایی نشان‌دهندهٔ running نیست. heartbeat قدیمی، فایل بزرگ، ساختار ناشناخته، hardlink یا reparse رد می‌شود. کد ربات، EA، تنظیمات، ریسک، سفارش‌ها و فایل‌های حساب خوانده/تغییر/کپی نشده‌اند. scanner کل دیسک وجود ندارد. کنترل مسیر در مقابل مهاجم محلی هم‌زمان، sandbox ویندوز یا جایگزین ACL و handle معتبر نیست.

## نتیجهٔ اجرای زنده

آزمون واقعیِ راه احراز هویت ازپیش‌موجود انجام شد: `git credential fill` در فرایند محلی با ورودی ثابت GitHub و prompt/trace غیرفعال، credential قابل استفاده نداد. helper نصب است اما پاسخ آن exit128 و بدون فیلد password بود؛ خطای خام و هیچ credential منتشر نشد. علت داخلی با جزئیات خصوصی استنتاج نشد. دو بررسی تشخیصی محدود نیز بدون token و بدون اجرای پل همین عدم دسترسی را تأیید کردند؛ تلاش خودکار تکراری متوقف شد. ابزار GitHub متصل به ChatGPT برای گزارش استفاده شده و معادل احراز هویت محلی پل نیست.

نتیجهٔ supervisor: `BLOCKED_LOCAL_AUTH` و `live_bridge_executed=false`. فایل BAT، polling زنده، ارسال نتیجهٔ handshake و اتصال SDK/MT5 اجرا نشده‌اند؛ پس `AMIN-WIN-RESULT-v1` واقعی برای این اجرا تأیید نمی‌شود و پاسخ ساختگی با آن پیشوند در GitHub ارسال نشده است. گزارش کد، پاسخ handshake محسوب نمی‌شود.

راه‌انداز اختیاری `local_secret_once.py` برای ورود مخفی **توسط خود مالک در کنسول محلی** آماده است؛ ورودی pipe/noninteractive را رد می‌کند و بدون تأیید YES حتی credential نمی‌خواند. توکن باید محدود به همین repo و Issues read/write با انقضا باشد؛ در فایل یا credential store ذخیره نمی‌شود و فقط برای فرزند یک‌باره استفاده می‌شود. این مسیر هنوز اجرا نشده و تأیید محلی تازهٔ مالک برای بازکردن پنجره خواسته شده است؛ پاسخ این سؤال جای خودِ ورود محلی را نمی‌گیرد. token هرگز نباید در چت/Issue نوشته شود. مسیر اجرای محلی و انتخاب نشست/فایل ربات در GitHub منتشر نمی‌شوند.

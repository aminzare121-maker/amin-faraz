# دستور ادامهٔ کار از گفت‌وگوی جدید

وقتی کاربر می‌گوید **«مخزن ابزارها»** یا **«ابزار مخزن»**:

۱. ابزار را «پروژهٔ تازه» فرض نکن. ابتدا GitHub متصل را بخوان:
```
repository = aminzare121-maker/amin-faraz
ref        = tools-makhzan-hub
path       = tools-makhzan/REGISTRY.json
```
۲. شناسه و نام ابزار درخواست‌شده را از فهرست پیدا کن؛ برای ویدئو `VIDEO-001` است. سپس پروندهٔ `tools-makhzan/VIDEO_ENGINE_STATE_FA.md` را بخوان.
۳. نسخهٔ کد را از **همان شاخه‌ای** بگیر که در Registry نوشته شده؛ در مورد ویدئو: `review/artin-teacher-av-understanding-v5-20261107` و PR #53. صرفِ وجود این PR به معنی ادغام با شاخهٔ اصلی نیست.
۴. لینک فیلمی که قبلاً پردازش شده با Registry تطبیق داده شود. فیلم مدرس از نشانی `https://my.uupload.ir/p/aGgKYdpL` **قبلاً دریافت و ۱۷ قسمتش رونویسی و ادغام شده**؛ مگر کاربر مشخصاً بخواهد تکرار یا آزمون روش جدید اجرا شود، آن را از صفر امتحان نکن.
۵. در هر پاسخ، **آزمون عملی موفق** و **فهم محتوای تأییدنشده** جدا نوشته شوند. برای استخراج قوانین قابل اجرا فقط شاهد قابل ردیابی، بررسی اصلاحات مدرس و سنجش خطا معتبر است؛ اگر مبهم باشد از وضعیت `REVIEW_REQUIRED` خارج نشود.
۶. اگر دسترسی GitHub قطع بود، به جای وانمود کردن به دسترسی، فقط محل دقیق مرجع را بگو و برای بازیابی مجدد اتصال اقدام کن؛ از کاربر نخواه تمام پروژه را از ابتدا تعریف کند.
۷. بعد از هر تغییر واقعی، تاریخ، commit/PR/CI و کار ناتمام را در `REGISTRY.json` و پرونده وضعیت اصلاح کن. ابزارهای جدید را با شناسهٔ جدید `VIDEO-002` یا `TOOL-002` و مسیر مستقل وارد فهرست کن.

## ادعای غیرمجاز
هیچ‌گاه فقط بر اساس تعداد تست‌های برنامه، **فهم صحیح تمام کلاس یا دقت صفرخطا** را اعلام نکن. بازشدن گفت‌وگوی جدید مساوی با انتقال خودکار زمینهٔ پنهانِ گفتگو نیست؛ این پرونده برای بازیابی صریح طراحی شده است.

## رشتهٔ آماده برای گفت‌وگوی جدید
«مخزن ابزارها را از GitHub `aminzare121-maker/amin-faraz`، شاخهٔ `tools-makhzan-hub` بخوان و کار `VIDEO-001` را از بخش NEXT_ACTION ادامه بده، بدون شروع دوبارهٔ همان فیلم.»


## عملیات اجرایی ثبت‌شده — فقط بازیابی فایل‌ها کافی نیست

پس از خواندن `REGISTRY.json`، اگر کاربر خواست **اجرا** شود، از طریق ابزار GitHub `mcp__GitHub__update_file` فایل `tools-makhzan/requests/current.json` در شاخهٔ `tools-makhzan-hub` را با SHA به‌روزرسانی کن. قالب فرمان:

```json
{
  "schema": "makhzan_tool_execution_request_v1",
  "tool_id": "VIDEO-001",
  "action": "build_review",
  "job_id": "artin-review-unique-20261107",
  "source_id": "TEACHER_J2_2026_11_07"
}
```

این تغییر `.github/workflows/tools-makhzan-executor.yml` را **واقعاً** فعال می‌کند. وضعیت اجرا را از GitHub Actions بررسی و نتیجهٔ موفق/ناموفق را با لینک واقعی اعلام کن؛ فقط ساختن فایل فرمان به معنی انجام عملیات نیست.

برای بررسی زنده `action=status`، برای ساخت بستهٔ بازبینی `action=build_review` و برای لینک **جدید که کاربر اجازه داده** `action=source_ingest` به همراه `source_url` و `ingest_mode` استفاده کن. حالت سوم هنوز اجرای کامل گفتار و قواعد آرتین نیست.

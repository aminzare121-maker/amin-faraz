# هوش پشتیبان امین — توسعهٔ مرحله‌ای تا قبولی واقعی

## دسترسی از گوشی اندروید و ویندوز با موتور مشترک

نسخه بومی Android تحت `android-client/` اضافه شده است: فارسی، فهرست نرم‌افزارهای مجاز، پرسش، پاسخ و منابع، کلید رمزگذاری‌شده در Android Keystore، و اتصال فقط HTTPS به همان موتور عمومی پشتیبانی. این کلاینت با برنامه مستقل «برنامه جواب» تداخل ندارد و اشتراک پولی جدید درخواست نمی‌کند. [جزئیات و محدودیت‌های اندروید](android-client/README_FA.md).

**این یک کلاینت متصل به موتور مرکزی است، نه اجرای مستقل هوش مصنوعی روی گوشی.** موتور باید روشن و از گوشی با HTTPS معتبر قابل دسترسی باشد؛ این اتصال و کیفیت پاسخ هنوز روی گوشی واقعی آزمایش نشده و حالت آفلاین مدل هنوز وجود ندارد. یکسانی دانش به‌معنی ذخیره‌شدن تاریخچه همه مکالمات دو دستگاه نیست.



## اصل قطعی مالک: هیچ پرداخت اجباری به GitHub یا مدل خارجی

حالت پیش‌فرض موتور `AMIN_ZERO_PAYMENT_MODE=on` است. درخواست به مدل خارجی در این حالت قطع است، حتی اگر API key و رضایت ارسال فراهم باشد. مدل محلی روی رایانه مالک تنها مسیر استنتاج فعال است؛ اگر در دسترس نباشد سامانه به مدارک و ارجاع انسانی برمی‌گردد. فایل `windows/Start-AminSupport-Free.ps1` اجرای آزمایشی محلی را بدون خرید یا دانلود خودکار آغاز می‌کند. ساخت کد و APK با اجراکننده‌های استاندارد GitHub فقط در مخزن عمومی رایگان است؛ ابزار `audit_free_github.py` استفاده از برچسب‌های ناشناس/احتمالاً پولی را در CI رد می‌کند. GitHub Actions برای استقرار دائم مدل یا پایگاه داده کاربران استفاده نمی‌شود.

**محدودیت:** این حالت، عدم خرید سرویس جدید را در کد کنترل می‌کند؛ برق، اینترنت و سخت‌افزار رایگان نمی‌شوند و به تنظیمات صورت‌حساب GitHub دسترسی نداریم. جزئیات، اقدامات باقی‌مانده و مسیر راه‌اندازی در [ZERO_PAYMENT_MODE_FA.md](ZERO_PAYMENT_MODE_FA.md) ثبت شده است.


## سهمیه رایگان و فروش اعتبار اضافه به نفع مالک نرم‌افزار

**اصل تجاری:** مشتریِ نرم‌افزار برای استفاده بیشتر، به **مالک سامانه پشتیبانی** پرداخت می‌کند؛ GitHub فروشنده سهمیه مشتری یا دریافت‌کننده خودکار وجه این نرم‌افزار نیست. هزینه‌های GitHub Actions/مدل/هاستینگ موضوع مستقلی است. قیمت، واحد پول و ارائه‌دهنده پرداخت هنوز انتخاب/تنظیم نشده‌اند.

**تفاوت دو سقف:** محدودیت ۳۰ سؤال و ۸ تیکت *در هر دقیقه* برای مهار مصرف بی‌رویه منابع باقی می‌ماند؛ خرید اعتبار آن را دور نمی‌زند. **سهمیه تجاری ماهانه** یک لایه جدید و مستقل است که مدیر برای هر کلید مشتری تعیین می‌کند. کلیدهای قدیمی برای حفظ سازگاری تا فعال‌کردن دستی این سقف، بدون سهمیه تجاری هستند؛ بنابراین هنوز نمی‌توان ادعا کرد دریافت پول برای همه مشتریان اجباری شده است.

### فعال‌سازی تجاری برای یک مشتری

مدیر از دستور `issue-access` شناسه `token_id` را دریافت می‌کند. سپس، در محیط معتمد و نه از طریق وب‌سایت عمومی:

```bash
python amin_support.py configure-quota --token-id TOKEN_ID --free-chat 100 --free-ticket 10
python amin_support.py quota-status --token-id TOKEN_ID
```

این اعداد **فقط نمونه قابل‌تغییر** هستند و قیمت یا سهمیه نهایی محصول نیستند. پس از مصرف سهمیه رایگان، سرویس با HTTP 402 و پیام «خرید اعتبار از مالک نرم‌افزار» درخواست را رد می‌کند. پس از آنکه مدیر پرداخت را از طریق یک روش مالی واقعی و خارج از این سامانه **مستقلاً بررسی کرد**، می‌تواند اعتبار اضافه کند:

```bash
python amin_support.py grant-credits --token-id TOKEN_ID --receipt-ref CONFIRMED-RECEIPT-0001 --chat-units 200 --ticket-units 10 --verified-by owner-admin
```

- ثبت هر رسید، به‌دلیل یکتابودن مرجع، بیش از یک بار ممکن نیست.
- اعتبار خریداری‌شده با آغاز ماه بعد از بین نمی‌رود؛ سهمیه رایگان ماهانه در ابتدای ماه UTC از نو محاسبه می‌شود.
- اعتبار در SQLite نگهداری و به هر کلید مشتری و نرم‌افزار مشخص محدود می‌شود؛ یک برنامه به سهمیه برنامه دیگر دسترسی ندارد.
- API عمومی **هیچ مسیری برای اعلام پرداخت، ساخت اعتبار یا دست‌کاری موجودی ندارد**. ارسال عکس فیش یا عبارت «پرداخت کردم» در پیام مشتری باعث افزایش اعتبار نمی‌شود.
- خطاهای اعتبارسنجی و خطاهای اجرای درخواست نباید مصرف اعتبار محسوب شوند.
- کلید مشترک قدیمی محیط تست، به‌قصد سازگاری حفظ شده و برای مشتریان تجاری نباید استفاده شود.

**هنوز تکمیل نشده:** اتصال واقعی درگاه پرداخت به نام مالک، تأیید پرداخت مستقل و غیرقابل‌جعل از شرکت پرداخت، صورتحساب، قیمت‌گذاری و مالیات، سطح دسترسی مدیران، شرایط بازپرداخت، امنیت استقرار و آزمایش تراکنش مالی واقعی. موفقیت آزمون SQLite/HTTP به معنی دریافت پول یا راه‌اندازی فروش نیست.


## جلوگیری از فشار غیرعادی روی مدل و هزینه سرور

برای حفاظت از CPU کم‌ظرفیت و هزینهٔ اجرای مدل، روی API کلیدهای **محدود به نرم‌افزار** یک سقف ساده اضافه شده است: هر کلید حداکثر ۳۰ سؤال و ۸ درخواست تیکت در بازه لغزان ۶۰ ثانیه می‌فرستد؛ درخواست بیشتر با HTTP 429 رد می‌شود. حداکثر دو پاسخ مدل هم‌زمان در یک فرایند قابل اجرا است و درخواست مازاد با 503 رد می‌شود تا منابع سیستم بی‌حد مصرف نشوند.

این حدود **فقط در حافظه یک فرایند** ثبت می‌شوند، با خاموش و روشن‌شدن سرور صفر می‌شوند و میان چند سرور مشترک نیستند. از این رو مانع حمله گسترده اینترنتی یا سوءاستفاده چندکاربره تضمین‌شده نیستند؛ برای عرضه تجاری باید سهمیه مشترک، صف و backpressure واقعی، پایش هزینه و محدودسازی بر مبنای هویت مشتری و سازمان افزوده شود. حالت قدیمی آزمایش محلی برای سازگاری، از سقف هر کلید مستثناست. هیچ خرید اشتراک یا سرویس جدید انجام نشده است.


## کنترل دسترسی مستقل هر نرم‌افزار — درگاه مشتری

در نسخه بعدی، یک کلید عمومی مشترک نباید اطلاعات تمام نرم‌افزارها را در اختیار یک مشتری بگذارد. برای هر نرم‌افزار یک کلید تصادفی با آنتروپی بالا و محدوده همان نرم‌افزار صادر می‌شود و در SQLite فقط هش آن ذخیره می‌گردد. کلید به شکل یک‌بارنمایش از خط فرمان معتمد صادر می‌شود:

```bash
python amin_support.py issue-access --project faraz
python amin_support.py issue-access --project faraz --allow-ticket
python amin_support.py list-access --project faraz
python amin_support.py revoke-access --token-id TOKEN_ID
```

- کلید بدون `--allow-ticket` فقط اجازه سؤال در نرم‌افزار خودش دارد؛ حتی اگر شناسه برنامه دیگری را در درخواست بفرستد، API آن را رد می‌کند.
- برای `/api/projects`، دارنده کلید فقط نام و وضعیت **همان نرم‌افزار** را می‌بیند.
- هنگام لغو کلید، درخواست بعدی همان کلید بلافاصله رد می‌شود. خود توکن به صورت متن در DB ذخیره نمی‌شود.
- `serve --scoped-only` در حالت localhost نیز کلیدهای قدیمی مشترک و دسترسی بی‌کلید را رد می‌کند؛ این حالت برای استفاده پشت **reverse proxy معتبر HTTPS** است.
- برای گوش‌دادن مستقیم روی آدرس غیرمحلی، **گواهی و کلید TLS واقعی** ضروری است:
  `serve --host 0.0.0.0 --port 8765 --tls-cert /secure/cert.pem --tls-key /secure/key.pem`.
  بدون کلید دسترسی محدود به نرم‌افزار یا بدون گواهی TLS، سرور نباید درگاه شبکه را باز کند.
- به منظور حفظ محیط آزمایش قبلی، حالت **localhost بدون `--scoped-only`** همچنان از کلید مشترک پیشین پشتیبانی می‌کند؛ این حالت برای ارائه عمومی توصیه نمی‌شود.

**محدودیت مهم:** کلید یک نرم‌افزار، هویت شخص حقیقی یا احراز هویت مدیر نیست. برای عرضه تجاریِ چندشرکتی، ورود مجزا و ثبت رویداد کاربران واقعی، مدیریت سطوح دسترسی، محدودسازی نرخ درخواست، ضد سوءاستفاده، گواهی معتبر و آزمون نفوذ باید تکمیل شوند. آزمون HTTP محلی فقط محدودسازی فعلی را نشان می‌دهد، نه آمادگی عرضه اینترنتی.


## حفاظ ارسال سؤال و مستندات به مدل خارجی — پیش‌فرض ممنوع

**همه نرم‌افزارهای ثبت‌شده:** استفاده از مدل محلی روی همین رایانه با آدرس `localhost` یا `127.0.0.1` بدون ارسال به سرویس خارجی پشتیبانی می‌شود. اگر آدرس مدل HTTPS بیرونی تنظیم شود، صرف آدرس و کلید API مجوز ارسال سؤال، اسناد یا بازخورد مشتری **نیست**.

برای هر ارسال خارجی، دو مجوز مستقل لازم است: 
۱) مدیر سامانه باید به‌صورت صریح `AMIN_MODEL_REMOTE_CONSENT=allow` را در محیط خدمت‌رسانی تنظیم کند.
۲) **صاحب همان درخواست** باید در همان سؤال، گزینه مجزای «ارسال به مدل خارجی» را روشن کند. این گزینه پیش‌فرض خاموش است و مستقل از رضایت ذخیره تیکت کار می‌کند.

برای متن‌های داخلی توسعه‌دهنده، مجوز سوم مدیر `AMIN_MODEL_INTERNAL_CONSENT=allow` نیز لازم است. در CLI از `--external-model-consent` استفاده می‌شود. در API، تنها مقدار بولی واقعی `external_model_consent: true` به منزله رضایت همان درخواست در نظر گرفته می‌شود؛ متن‌هایی مانند `"true"` مجوز نیستند.

**محدودیت:** این یک محافظ انتقال داده در کد است، نه سامانه آماده عرضه از نظر حریم خصوصی. تا قبل از احراز هویت مستقل کاربران، سیاست نگهداری/حذف اطلاعات نزد ارائه‌دهنده، کنترل دسترسی شبکه و آزمون واقعی، نباید داده حساس به سرویس خارجی ارسال شود. آزمون‌های unit با سرور ساختگی تنها نشان می‌دهند درخواست بدون مجوز از دستگاه خارج نمی‌شود؛ مجوز تجاری یا رضایت قانونی را تأیید نمی‌کنند.


## موتور عمومی برای هر نرم‌افزار و یادگیری کنترل‌شده — مرحله آزمایشی

این موتور **محدود به پروژه‌های امین نیست**. یک مدیر فنی می‌تواند از طریق خط فرمان مطمئن، برای هر نرم‌افزار جدید شناسه، نام، مسئول ثابت، پوشه اسناد مجاز و مسیرهای عمومی را ثبت کند. اطلاعات و تصمیم‌های هر برنامه در همان حوزه نگه داشته می‌شوند. مسئول ثابت از نظر ساختار ثبت می‌شود اما **شناسهٔ متنی او احراز هویت امنیتی نیست**؛ استقرار چندمشتری نیازمند ورود و کنترل دسترسی واقعی است.

```bash
python amin_support.py register-program --id shopdesk --name "برنامه مدیریت فروشگاه" --director-id director-shop --director-label "مدیر فروشگاه" --source-prefix docs --public-path docs/guide.md
python amin_support.py record-learning --project shopdesk --observation "مشکل ثبت گزارش موجودی در نسخه آزمایشی" --consent
python amin_support.py learning-pending --project shopdesk
python amin_support.py approve-learning --project shopdesk --director-id director-shop --feedback-id FEEDBACK_ID --problem "گزارش موجودی نمایش داده نمی‌شود" --solution "بر اساس راهنمای نسخه جاری، تنظیمات گزارش موجودی را بررسی کنید" --visibility public
python amin_support.py revoke-learning --project shopdesk --director-id director-shop --feedback-id FEEDBACK_ID
```

قوانین مهم:
- **ورود نرم‌افزار جدید:** مبتنی بر تنظیم مستقل؛ نیازی به تغییر نام‌های قبلی فراز/آرتین نیست.
- **هم‌سویی با مدیر:** فقط قالب‌های سبک تأییدشده (زبان، لحن، میزان جزئیات و سطح تخصص) استفاده می‌شوند؛ دستور آزاد از یک مشتری به دستور سیستم تبدیل نمی‌شود. تغییر سبک ثبت و قابل ردیابی است.
- **یادگیری:** بازخورد مشتری فقط با رضایت ثبت و تا تأیید مسئول در صف خصوصی باقی می‌ماند. مدیر باید جداگانه شرح عمومی و راه‌حل بی‌نام را بررسی و تأیید کند. تا قبل از آن وارد پاسخ‌ها نمی‌شود.
- **اصلاح اشتباه:** مدیر می‌تواند درس نادرست را از بازیابی حذف کند؛ تاریخچه تأیید و لغو حفظ می‌شود.
- **جداسازی:** سند محرمانه، بازخورد تأییدنشده، و دانش خصوصی یک نرم‌افزار نباید وارد پاسخ مشتری یا برنامه دیگر شود.
- **سنجش بهبود:** آزمون کوچک گذشته/بعد از افزودن درس، پیدا شدن پاسخ برای پرسش مرتبط را اندازه می‌گیرد؛ این **یادگیری مدل یا اثبات هوشمندتر شدن کلی** نیست.

وضعیت: کد و آزمون‌های مستقل نوشته شده‌اند. هنوز سرویس هویت چندمالک، آموزش مدل از داده، پذیرش روی مسئله‌های واقعی ده‌ها نرم‌افزار، اجرای پایدار و آزمون واقعی کاربران انجام نشده‌اند. استفاده عملی از این دستورها فقط روی محیط امن و کنترل‌شده مدیر مجاز است.



## ارتقای حافظهٔ راه‌حل‌های تأییدشده — نگهداری حریم خصوصی

در نسخهٔ جدید، هر تیکت دارای **متن خصوصی مشتری** و در صورت تأیید مدیر، **شرح عمومی و بی‌نام مشکل** جداگانه است. موتور می‌تواند سؤال‌های مشابه را با شرح عمومی تطبیق دهد، در حالی که پیام اصلی مشتری وارد متن پاسخ، مستندات بازگشتی و زمینهٔ ارسالی به مدل نمی‌شود.

برای تأیید مدیر از خط فرمان مطمئن:

    python amin_support.py approve-ticket --project faraz --id TICKET_ID --resolution "راه‌حل تأییدشده و عمومی" --public-problem "خلاصه عمومی مشکل بدون نام، شماره یا اطلاعات شخصی"

پرچم `--public-problem` اختیاری است؛ بدون آن، جست‌وجوی قدیمی بر پایه متن راه‌حل ادامه می‌یابد. داده‌های SQLite قدیمی با افزودن ستون جدید سازگار می‌شوند. مرور انسانی خلاصه عمومی ضروری است؛ هیچ عبارتی از تیکت خصوصی به‌طور خودکار عمومی نمی‌شود. این تغییر هنوز جایگزین ممیزی امنیتی و حریم خصوصی محیط تجاری نیست.


## آزمون واقعی مدل زبانی محلی — آزمایشی

در شاخه توسعهٔ این مرحله، Workflow به نام `Support Hub real local LLM pilot` یک سرویس موقت Ollama در GitHub Actions بالا می‌آورد، مدل عمومی `qwen2.5:7b-instruct` را دریافت می‌کند و دو آزمون روی **خود مدل واقعی** انجام می‌دهد:
- `model_probe.py`: اتصال و تولید متن فارسی از API واقعی محلی
- `real_model_smoke.py`: پاسخ یک سؤال فارسی درباره راهنمای فرضی با ارجاع معتبر به سند `README.md` در موتور `SupportEngine`

پروژه مشتری، کلید API، معاملات، داده شخصی و سورس داخلی به مدل ارسال نمی‌شوند؛ متن سند آزمون ساختگی و عمومی است. **مدل بسیار کوچک برای آزمون زیرساخت انتخاب شده است؛ مناسب‌بودن آن برای پشتیبانی فنی واقعی تأیید نشده.** مصرف منابع فقط هنگام اجرای این workflow موقت GitHub است. مجوز مدل پایه در [کارت رسمی Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct) از نوع Apache-2.0 اعلام شده است؛ استفاده تجاری نهایی مستلزم رعایت مجوز تمام اجزا است.

آزمون ابتدایی مدل کوچک `qwen2.5:0.5b-instruct` به شکل واقعی اجرا شد، ولی آزمون پاسخ مستند را رد کرد؛ مدل گاه فقط عنوان و شماره سند را بازمی‌گرداند. برای جلوگیری از پذیرفتن پاسخ بی‌معنا، فیلتر جدا و آزمون رگرسیون افزوده شد. آزمون واقعی مدل ۱٫۵ میلیارد پارامتری نیز پاسخ نامستند را رد کرد؛ اکنون مدل ۷ میلیارد پارامتری به‌صورت آزمایشی بررسی می‌شود. اگر GitHub از دریافت Docker image یا مدل به دلیل اینترنت یا ظرفیت بازبماند، نتیجه **ناموفق/مسدود** است؛ صرف موفقیت آزمون‌های مصنوعی جای آن را نمی‌گیرد. حتی قبولی این مدل در یک سؤال، دلیل قبولی هدف اصلی مالک نیست. استقرار دائمی روی رایانه، گوشی یا سرور انجام نشده است.


## نسخه ۰.۴ — آزمون سلامت اتصال مدل واقعی (برنامه جواب #۷۳)

برای جلوگیری از معرفی صرف رابط API به‌عنوان موتور هوشمند نصب‌شده، فایل model_probe.py اضافه شد.

فرمان مدیریتی از پوشه amin-ai-support:

    python model_probe.py

بدون تنظیم مدل نتیجه not_configured و کد خروج ناموفق برمی‌گردد. با تنظیم صریح AMIN_MODEL_BASE_URL و AMIN_MODEL_NAME و در صورت نیاز AMIN_MODEL_API_KEY، ابزار یک سؤال آزمایشی بدون داده شخصی یا سورس برنامه به مدل سازگار با API می‌فرستد. نتیجه جداگانه مشخص می‌کند سرویس پاسخ داده، خروجی نویسه فارسی داشته و تأخیر اندازه‌گیری‌شده چقدر بوده است. برای سرویس خارجی HTTPS و برای HTTP فقط نشانی loopback مجاز است.

**تست GitHub از پاسخ‌دهنده HTTP آزمایشی محلی استفاده می‌کند و هیچ مدل واقعی نصب یا اجرا نمی‌کند.** کیفیت استدلال، مجوز تجاری، عیب‌یابی کد و گفتار فارسی باید با مدل واقعی و داده آزمون مستقل تأیید شوند. ابزار بدون اجازه مدل یا اشتراک خریداری/نصب نمی‌کند، کلید API را نمایش نمی‌دهد و ادعای آماده‌بودن محصول ندارد.

## اجرای محلی

پیش‌نیاز: Python 3.11+ و Git. برای اجرای محلی پایه، کتابخانه Python اضافی لازم نیست.

~~~bash
cd amin-ai-support
python -m unittest discover -s tests -v
python amin_support.py sync --project faraz
python amin_support.py ask --project faraz --message "موتور فراز چه وضعیت مستندی دارد؟"
python amin_support.py serve
~~~

صفحه محلی: http://127.0.0.1:8765

برای افزودن نمایه آرتین، V5 یا کابین، به‌جای faraz شناسهٔ همان پروژه را وارد کنید. اجرای sync بدون شناسه، همه پروژه‌های دارای شاخه GitHub تعریف‌شده را بررسی می‌کند. sync به GitHub دسترسی شبکه نیاز دارد. اگر اتصال برقرار نباشد، دانش موجود از بین نمی‌رود.

بررسی و تأیید درخواست‌های ذخیره‌شده فقط از خط فرمان مورد اعتماد مدیر انجام می‌شود:

~~~bash
python amin_support.py tickets --project faraz
python amin_support.py approve-ticket --project faraz --id TICKET_ID --resolution "راه‌حل بررسی‌شده و تأییدشده"
~~~

این فرمان تنها برای مدیر است و به مشتری دسترسی آن داده نمی‌شود. ثبت تیکت به معنی حل‌شدن یا ارسال اعلان به مشتری نیست؛ سامانه اعلان و حساب کاربری هنوز ساخته نشده است.

برای به‌روزرسانی خودکار تا زمانی که فرایند اجراست:

~~~bash
python auto_sync.py --interval-seconds 21600
~~~

### اتصال به مدل هوش مصنوعی

**موتور مدل داخل این مخزن قرار ندارد.** برای تولید پاسخ تحلیلی، می‌توان مدل مجاز را روی سرور خود یا از سرویس سازگار با API متصل کرد:

~~~bash
export AMIN_MODEL_BASE_URL="http://127.0.0.1:11434/v1"
export AMIN_MODEL_NAME="YOUR_INSTALLED_MODEL"
export AMIN_MODEL_API_KEY=""
python amin_support.py serve
~~~

این مثال فقط قالب اتصال است؛ وجود یا نصب هیچ مدل خاصی را ادعا نمی‌کند. برای مدل بیرونی HTTPS الزامی است؛ ارسال مستندات و متن سؤال به سرویس بیرونی باید با رضایت و سیاست حریم خصوصی سازگار باشد. ورود صوتی مرورگر نیز ممکن است از سرویس ابری خود مرورگر استفاده کند و عملکرد آن با اینترنت محدود، تضمین‌شده نیست.

### امنیت و استفاده عمومی

- اجرای سرور به‌طور پیش‌فرض فقط روی 127.0.0.1 است. اگر روی نشانی عمومی یا شبکه باز شود، AMIN_SUPPORT_API_KEY اجباری می‌شود؛ اما کلید مشترک به‌تنهایی **احراز هویت تولیدی کاربران** نیست.
- برای عرضه واقعی باید HTTPS، حساب مستقل کاربران، جداسازی مستاجرها، محدودسازی درخواست، سیاست حذف اطلاعات و رصد امنیتی اضافه شود.
- API عمومی فقط نقش customer دارد؛ حتی اگر درخواست role=developer بفرستد. ابزارهای توسعه و عیب‌یابی از خط فرمان مدیر اجرا می‌شوند.
- فایل .env، کلید خصوصی، داده حجیم و مسیرهای نامرتبط وارد نمایه نمی‌شوند؛ الگوهای رایج رمز نیز پیش از ذخیره حذف می‌شوند. این فیلتر **ممیزی کامل اسرار نیست**؛ مخزن محرمانه نباید بی‌بررسی نمایه شود.
- هیچ دستور عملیاتی، اصلاح سورس، ارسال سفارش معاملاتی، تغییر حساب یا استقرار عمومی بدون کنترل جداگانه اجرا نمی‌شود.
- صدای فارسی مبتنی بر قابلیت مرورگر است؛ کیفیت، آفلاین‌بودن یا موجودبودن آن هنوز تضمین نشده است.

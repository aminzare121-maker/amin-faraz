# هوش پشتیبان امین — توسعهٔ مرحله‌ای تا قبولی واقعی

## جلوگیری از ارسال ناخواستهٔ داده‌ها به مدل‌های بیرونی

آداپتور مدل در `amin_support.py` به‌صورت پیش‌فرض فقط از سرویس محلی `http://127.0.0.1:PORT/v1` یا `localhost` استفاده می‌کند. **صرف تنظیم نشانی یک مدل خارجی باعث ارسال سؤال و اسناد پروژه به آن نخواهد شد.** برای فعال‌سازی سرویس HTTPS خارجی، مدیر ابتدا باید به‌صورت صریح متغیر محیطی `AMIN_MODEL_REMOTE_CONSENT=allow` را تنظیم کند. اگر قرار است اسناد داخلی توسعه‌دهنده نیز به آن سرویس ارسال شوند، اجازه مستقل `AMIN_MODEL_INTERNAL_CONSENT=allow` لازم است.

این دو مجوز صرفاً تنظیمات مدیر هستند، **نه رضایت مشتری نهایی**. پیش از استفاده تجاری با مدل خارجی، احراز هویت کاربران، اطلاع‌رسانی و رضایت هر درخواست، قرارداد پردازش داده و سیاست نگهداری داده‌ها باید جداگانه پیاده‌سازی و آزمایش شوند. تا آن زمان مدل خارجی برای سرویس عمومی توصیه نمی‌شود.

نشانی مدل برای رد URL مشکوک، اعتبار HTTP/HTTPS و محرمانگی اعتبارنامه‌ها بررسی می‌شود. مدل محلی همچنان بدون اجازه ارسال خارجی قابل اجراست. نمونهٔ تست: `python -m unittest discover -s tests -v`.


## ارتقای حافظهٔ راه‌حل‌های تأییدشده — نگهداری حریم خصوصی

در نسخهٔ جدید، هر تیکت دارای **متن خصوصی مشتری** و در صورت تأیید مدیر، **شرح عمومی و بی‌نام مشکل** جداگانه است. موتور می‌تواند سؤال‌های مشابه را با شرح عمومی تطبیق دهد، در حالی که پیام اصلی مشتری وارد متن پاسخ، مستندات بازگشتی و زمینهٔ ارسالی به مدل نمی‌شود.

برای تأیید مدیر از خط فرمان مطمئن:

    python amin_support.py approve-ticket --project faraz --id TICKET_ID --resolution "راه‌حل تأییدشده و عمومی" --public-problem "خلاصه عمومی مشکل بدون نام، شماره یا اطلاعات شخصی"

پرچم `--public-problem` اختیاری است؛ بدون آن، جست‌وجوی قدیمی بر پایه متن راه‌حل ادامه می‌یابد. داده‌های SQLite قدیمی با افزودن ستون جدید سازگار می‌شوند. مرور انسانی خلاصه عمومی ضروری است؛ هیچ عبارتی از تیکت خصوصی به‌طور خودکار عمومی نمی‌شود. این تغییر هنوز جایگزین ممیزی امنیتی و حریم خصوصی محیط تجاری نیست.


## آزمون واقعی مدل زبانی محلی — آزمایشی

در شاخه توسعهٔ این مرحله، Workflow به نام `Support Hub real local LLM pilot` یک سرویس موقت Ollama در GitHub Actions بالا می‌آورد، مدل عمومی `qwen2.5:7b-instruct` را دریافت می‌کند و دو آزمون روی **خود مدل واقعی** انجام می‌دهد:
- `model_probe.py`: اتصال و تولید متن فارسی از API واقعی محلی
- `real_model_smoke.py`: پاسخ یک سؤال فارسی درباره راهنمای فرضی با ارجاع معتبر به سند `README.md` در موتور `SupportEngine`

پروژه مشتری، کلید API، معاملات، داده شخصی و سورس داخلی به مدل ارسال نمی‌شوند؛ متن سند آزمون ساختگی و عمومی است. **مدل بسیار کوچک برای آزمون زیرساخت انتخاب شده است؛ مناسب‌بودن آن برای پشتیبانی فنی واقعی تأیید نشده.** مصرف منابع فقط هنگام اجرای این workflow موقت GitHub است. مجوز مدل پایه در [کارت رسمی Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct) از نوع Apache-2.0 اعلام شده است؛ استفاده تجاری نهایی مستلزم رعایت مجوز تمام اجزا است.

آزمون ابتدایی مدل کوچک `qwen2.5:0.5b-instruct` به شکل واقعی اجرا شد، ولی آزمون پاسخ مستند را رد کرد؛ مدل گاه فقط عنوان و شماره سند را بازمی‌گرداند. برای جلوگیری از پذیرفتن پاسخ بی‌معنا، فیلتر جدا و آزمون رگرسیون افزوده شد. آزمون واقعی مدل ۱٫۵ میلیارد پارامتری نیز پاسخ نامستند را رد کرد؛ اکنون مدل ۷ میلیارد پارامتری به‌صورت آزمایشی بررسی می‌شود. اگر GitHub از دریافت Docker image یا مدل به دلیل اینترنت یا ظرفیت بازبماند، نتیجه **ناموفق/مسدود** است؛ صرف موفقیت آزمون‌های مصنوعی جای آن را نمی‌گیرد. حتی قبولی این مدل در یک سؤال، دلیل قبولی هدف اصلی مالک نیست. استقرار دائمی روی رایانه، گوشی یا سرور انجام نشده است.


## نسخه ۰.۴ — آزمون سلامت اتصال مدل واقعی (برنامه جواب #۷۳)

برای جلوگیری از معرفی صرف رابط API به‌عنوان موتور هوشمند نصب‌شده، فایل model_probe.py اضافه شد.

بدون تنظیم مدل نتیجه not_configured و کد خروج ناموفق برمی‌گردد. با تنظیم صریح AMIN_MODEL_BASE_URL و AMIN_MODEL_NAME و در صورت نیاز AMIN_MODEL_API_KEY، ابزار یک سؤال آزمایشی بدون داده شخصی یا سورس برنامه به مدل سازگار با API می‌فرستد. نتیجه جداگانه مشخص می‌کند سرویس پاسخ داده، خروجی نویسه فارسی داشته و تأخیر اندازه‌گیری‌شده چقدر بوده است. برای سرویس خارجی HTTPS و برای HTTP فقط نشانی loopback مجاز است.

**تست GitHub از پاسخ‌دهنده HTTP آزمایشی محلی استفاده می‌کند و هیچ مدل واقعی نصب یا اجرا نمی‌کند.** کیفیت استدلال، مجوز تجاری، عیب‌یابی کد و گفتار فارسی باید با مدل واقعی و داده آزمون مستقل تأیید شوند. ابزار بدون اجازه مدل یا اشتراک خریداری/نصب نمی‌کند، کلید API را نمایش نمی‌دهد و ادعای آماده‌بودن محصول ندارد.

## هدف ثابت مالک

یک موتور مشترک که برای هر محصول حافظه، مجوز، ابزار عیب‌یابی و پاسخ‌گویی فارسی جدا داشته باشد. توسعه و پشتیبانی پروژه‌ها باید از نسخه واقعی کد و شواهد قابل ردیابی پیروی کند. سابقه تصمیم‌های ChatGPT و Codex صرفاً تا حدی قابل استفاده است که در فایل، Issue، PR، گزارش آزمون یا منابع مجاز دیگری ثبت شده باشد؛ امکان انتقال مستقیم «تمام ادراک» درونی مدل‌ها وجود ندارد.

## اجرای محلی

پیش‌نیاز: Python 3.11+ و Git. برای اجرای محلی پایه، کتابخانه Python اضافی لازم نیست.

~~~bash
cd amin-ai-support
python -m unittest discover -s tests -v
python amin_support.py sync --project faraz
python amin_support.py ask --project faraz --message "موتور فراز چه وضعیت مستندی دارد؟"
python amin_support.py serve
~~~

صفحه محلی: http://127.0.0.1:8765

برای افزودن نمایه آرتین، V5 یا کابین، به‌جای faraz شناسهٔ همان پروژه را وارد کنید. اجرای sync بدون شناسه، همه پروژه‌های دارای شاخه GitHub تعریف‌شده را بررسی می‌کند. sync به GitHub دسترسی شبکه نیاز دارد. اگر اتصال برقرار نباشد، دانش موجود از بین نمی‌رود.

بررسی و تأیید درخواست‌های ذخیره‌شده فقط از خط فرمان مورد اعتماد مدیر انجام می‌شود:

~~~bash
python amin_support.py tickets --project faraz
python amin_support.py approve-ticket --project faraz --id TICKET_ID --resolution "راه‌حل بررسی‌شده و تأییدشده"
~~~

این فرمان تنها برای مدیر است و به مشتری دسترسی آن داده نمی‌شود. ثبت تیکت به معنی حل‌شدن یا ارسال اعلان به مشتری نیست؛ سامانه اعلان و حساب کاربری هنوز ساخته نشده است.

برای به‌روزرسانی خودکار تا زمانی که فرایند اجراست:

~~~bash
python auto_sync.py --interval-seconds 21600
~~~

### اتصال به مدل هوش مصنوعی

**موتور مدل داخل این مخزن قرار ندارد.** برای تولید پاسخ تحلیلی، می‌توان مدل مجاز را روی سرور خود یا از سرویس سازگار با API متصل کرد:

~~~bash
export AMIN_MODEL_BASE_URL="http://127.0.0.1:11434/v1"
export AMIN_MODEL_NAME="YOUR_INSTALLED_MODEL"
export AMIN_MODEL_API_KEY=""
python amin_support.py serve
~~~

این مثال فقط قالب اتصال است؛ وجود یا نصب هیچ مدل خاصی را ادعا نمی‌کند. برای مدل بیرونی HTTPS الزامی است؛ ارسال مستندات و متن سؤال به سرویس بیرونی باید با رضایت و سیاست حریم خصوصی سازگار باشد. ورود صوتی مرورگر نیز ممکن است از سرویس ابری خود مرورگر استفاده کند و عملکرد آن با اینترنت محدود، تضمین‌شده نیست.

### امنیت و استفاده عمومی

- اجرای سرور به‌طور پیش‌فرض فقط روی 127.0.0.1 است. اگر روی نشانی عمومی یا شبکه باز شود، AMIN_SUPPORT_API_KEY اجباری می‌شود؛ اما کلید مشترک به‌تنهایی **احراز هویت تولیدی کاربران** نیست.
- برای عرضه واقعی باید HTTPS، حساب مستقل کاربران، جداسازی مستاجرها، محدودسازی درخواست، سیاست حذف اطلاعات و رصد امنیتی اضافه شود.
- API عمومی فقط نقش customer دارد؛ حتی اگر درخواست role=developer بفرستد. ابزارهای توسعه و عیب‌یابی از خط فرمان مدیر اجرا می‌شوند.
- فایل .env، کلید خصوصی، داده حجیم و مسیرهای نامرتبط وارد نمایه نمی‌شوند؛ الگوهای رایج رمز نیز پیش از ذخیره حذف می‌شوند. این فیلتر **ممیزی کامل اسرار نیست**؛ مخزن محرمانه نباید بی‌بررسی نمایه شود.
- هیچ دستور عملیاتی، اصلاح سورس، ارسال سفارش معاملاتی، تغییر حساب یا استقرار عمومی بدون کنترل جداگانه اجرا نمی‌شود.
- صدای فارسی مبتنی بر قابلیت مرورگر است؛ کیفیت، آفلاین‌بودن یا موجودبودن آن هنوز تضمین نشده است.

## شاخص‌های قبولی پیش از استفاده تجاری

- آزمون با مسائل واقعی هر پروژه؛ هدف پیشنهادشده دست‌کم 85٪ پاسخ درست و مستند بر اساس مجموعه آزمون از پیش تعریف‌شده.
- صفر پاسخ بین‌پروژه‌ای، صفر افشای داده محرمانه در تست امنیت، صفر تغییر حساس بدون مجوز.
- ارزیابی جداگانه کیفیت گفتار فارسی، تشخیص خطا، هزینه مدل، سرعت و پایداری شبکه.
- بررسی پروانه نرم‌افزار و مدل‌ها برای استفاده تجاری.

**این معیارها هنوز پاس نشده‌اند.** اجرای موفق چند تست واحد به‌معنای تأیید عملکرد واقعی یا آمادگی کاربران نیست.

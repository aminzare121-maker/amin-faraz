# صدای عصبی زندهٔ «هوش امین» — اتصال واقعی به اندروید

## کار اجرایی انجام‌شده

`neural_live_voice.py` یک **تولیدکنندهٔ واقعی موج عصبی فارسی** با مدل VITS/Piper دارای مجوز CC-BY-4.0 است؛ بدون API پولی و بدون Codex/Work. مدل با یک فرآیند محلی **در میزبان صوتیِ مجاز** صدای PCM با نرخ 22050 هرتز می‌سازد. از متن محرمانه برای لاگ، فایل دائمی، issue یا GitHub Actions استفاده نمی‌شود؛ فایل صوتی موقت بعد از پردازش پاک می‌شود.

`live_bridge.py` با `AMIN_NEURAL_VOICE_ENABLE=1` می‌تواند صدای پاسخ همان مدل پاسخ‌گو را پس از پاسخ متنی، به‌صورت قطعه‌های دارای `id` و `SHA-256` روی همان WSS رمزگذاری‌شده بفرستد. فقط **توکن مالک** اجازه دارد از این موتور استفاده کند؛ سهمیهٔ ChatGPT مالک به کاربران دیگر منتقل نمی‌شود.

`NeuralVoicePlayer.java` در اندروید این قطعه‌ها را بدون دانلود ONNX به گوشی دریافت می‌کند، ساختار PCM، شناسه، ترتیب، شمار قطعه و اثرانگشت را بررسی و با `AudioTrack` پخش می‌کند. پاسخ متنی منتظر صدای عصبی می‌ماند تا دوباره با TTS اندروید خوانده نشود. قطع دستی، قطع اتصال، خطا و مهلت انتظار مدیریت می‌شوند. اگر صدا از ابتدا در دسترس نباشد، پاسخ متنی با TTS اندروید خوانده می‌شود؛ اگر بخشی از صدای عصبی پخش شد، پاسخ از اول تکرار نمی‌شود.

**این قابلیت در کد وجود دارد، اما تا اجرای میزبان واقعی و احراز هویت روی Galaxy M62، نصب و کارکرد واقعی تأیید نشده است.** GitHub Actions فقط می‌تواند تولید WAV را با مدل واقعی به‌طور محدود **آزمون** کند؛ سرور دائمی WSS نیست.

## راه‌اندازی روی میزبان آنلاین مجاز (نه گوشی/لپ‌تاپ مالک)

این بخش فقط برای سیستمی است که مالک تأیید کرده مدل روی آن قرار بگیرد. هزینه یا سرویس جدیدی خودکار ساخته نمی‌شود.

۱. کد را از `aminzare121-maker/amin-faraz` به میزبان منتخب دریافت کنید؛ محیط Python 3.11+ و پکیج متن‌باز `piper-tts==1.3.0` را **فقط روی میزبان صوتی** نصب کنید.

۲. مدل فارسی مجوزدار را روی میزبان قرار دهید، نه روی Android/Windows. مدل پایه: <https://huggingface.co/alifthi/persian-TTS/tree/main/onnx> . دو فایل `model.onnx` و `model.onnx.json` باید هم‌نسخه باشند. نام و مجوز سازنده **Ali Fathi — CC-BY-4.0** باید همراه خروجی/محصول ذکر شود.

۳. متغیرهای میزبان را تنظیم کنید:

```bash
export AMIN_NEURAL_VOICE_ENABLE=1
export AMIN_NEURAL_MODEL_PATH=/srv/amin-voice/model.onnx
export AMIN_NEURAL_CONFIG_PATH=/srv/amin-voice/model.onnx.json
export AMIN_NEURAL_SPEAKER_ID=2
export AMIN_LIVE_OWNER_TOKEN_ID='<id-of-the-existing-program-scoped-owner-token>'
```

۴. `live_bridge.py` را با پروژه‌ها، پایگاه داده و توکن‌های scoped موجود، HTTPS/WSS واقعی و گواهی معتبر اجرا کنید. برای استفاده از مدل پاسخ‌گوی ChatGPT-plan، مسیر `AMIN_SIWC_ENABLE=1` فقط بعد از ورود OAuth حقیقی و در حدود شرایط مجاز حساب فعال می‌شود؛ پیکربندی صوت، به‌خودی‌خود ChatGPT را احضار نمی‌کند. هرگونه سرویس آنلاین رایگان یا پایدار بودن میزبان باید مستقلاً احراز شود.

۵. در اپ اندروید، WSS مجاز را وارد و احراز هویت کنید؛ گزینهٔ «صدای عصبی فارسی آنلاین امین» را فعال نگه دارید. اگر در پاسخ `ready` عبارت `neural_voice_ready=true` دیده شود و درخواست با `neural_voice=true` ارسال شود، پاسخ `voice_pending` و سپس `voice_frame`ها را دریافت خواهد کرد. **حالت آفلاین اجباری** هیچ درخواستی برای صدای عصبیِ اینترنتی ارسال نمی‌کند.

## محدودیت‌های قطعی

- مدل ۷۶ مگابایتی روی گوشی/رایانهٔ مالک قرار نمی‌گیرد. باید روی یک **میزبان آنلاینِ واقعاً در دسترس و دارای منابع CPU** قرار بگیرد. هنوز چنین میزبان ۲۴ساعته‌ای مستقر نشده است.
- GitHub مخزن/CI و محل نمونه‌های صوتی است. <https://docs.github.com/en/actions/reference/limits> زمان هر Job محدود است و GitHub Actions یک میزبان WSS دائمی نیست. اجرای Actions برای هر جمله هم مکالمهٔ کم‌تأخیر فراهم نمی‌کند؛ انتشار متن خصوصی در مخزن عمومی نیز ممنوع است.
- نمونه‌های مدل موجود برای طراحی صدای پایه‌اند؛ هنوز صدای عصبیِ تازه از صفر آموزش داده نشده است. کیفیت انسانیِ برابر Live ChatGPT بدون آزمون شنیداری و مقایسهٔ قابل‌تکرار تأیید نشده.
- کیفیت تشخیص گفتار فارسی به سرویس اندروید گوشی وابسته است. این تغییر، خودِ مدل ASR جدیدی به گوشی نصب نمی‌کند.
- هیچ کلید API پولی، اشتراک تازه، پرداخت یا سرور خریداری/فعال نشده است.
- هر پاسخ صوتی تا ۷ بخش محدود با کنترل طول، نرخ و اندازهٔ فایل است تا حافظه و شبکهٔ گوشی با فایل‌های حجیم پر نشود.

## معیار آزمایش و تکمیل

آزمون GitHub CI برای Python، WSS و `NeuralAudioPolicy` و ساخت APK باید موفق باشد. اجرای جداگانهٔ مدل واقعی Piper روی GitHub Actions باید `PCM` معتبر از **همین کلاس عملیاتی** تولید کند. بعد از آن، مسیر یکپارچهٔ گوشی و WSS با توکن واقعی، صدای واقعی و توقف گفتار باید آزمایش شود. فقط پس از آزمون شنیداری فارسی و تأیید مالک می‌توان از «کیفیت پذیرفته‌شده» صحبت کرد.

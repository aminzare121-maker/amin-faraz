# عامل اجرایی ChatGPT برای GitHub — بدون Codex، Work و API پولی

## چه چیزی پیاده‌سازی شده است؟

این یک **عامل متن‌باز اجراشونده روی لپ‌تاپ صاحب حساب** است. بعد از ورود رسمی **Sign in with ChatGPT**، مدل واجد شرایط حساب ChatGPT از طریق Responses API عمومی (OAuth سهمیهٔ اشتراک، نه API Key پولی) می‌تواند ابزارهای GitHub را فراخوانی کند:

- `github.repository_info`: محدودهٔ همین پروژه و وضعیت کار
- `github.list_files` و `github.read_file`: خواندن پوشه/فایل و SHA نسخه
- `github.create_branch`: شاخهٔ اختصاصی `amin-ai-plan/<request_id>` برای هر درخواست
- `github.write_file`: نوشتن فایل **فقط در همین شاخه**، کنترل SHA برای جلوگیری از بازنویسی اشتباه
- `github.create_pull_request`: ایجاد Pull Request **پیش‌نویس** و بدون ادغام
- `github.check_ci`: مشاهدهٔ اجراهای GitHub Actions، نه جعل موفقیت آزمون

مدل خروجی هر تابع را در مرحلهٔ بعد می‌بیند و برای ادامهٔ کار تصمیم می‌گیرد؛ یک درخواست می‌تواند چند عملیات متوالی داشته باشد. فایل‌های مخزن ممکن است حاوی دستورات مخرب باشند؛ محتوای فایل‌ها **داده** محسوب می‌شوند، نه دستور مجوزدهنده.

پیاده‌سازی در `github_agent_tools.py` و `chatgpt_git_agent.py` است؛ با `store:false` و `stream:true` و یک زنجیرهٔ کامل ورودی/خروجی در درخواست‌های بعدی. درخواست‌های مدل فقط بعد از مشاهدهٔ `response.completed` معتبر هستند؛ شکست اتصال یا تمام‌شدن سهمیه بعد از خروجی جزئی هرگز منجر به اجرای آن دستور نمی‌شود. ابزار `tool_search` و `previous_response_id` برای مسیر SIWC استفاده نشده‌اند.

## شروع روی ویندوز

بعد از دریافت آخرین نسخهٔ مخزن (برای روش ورود اول):

```powershell
cd amin-ai-support
python -m pip install -r requirements-siwc.txt
python chatgpt_plan_direct.py login
python chatgpt_plan_direct.py status
python chatgpt_plan_direct.py models
```

ورود به ChatGPT و تأیید استفاده از سهمیه را **خود صاحب حساب** در مرورگر رسمی OpenAI انجام می‌دهد. این حساب به مرورهای خصوصی همین گفت‌وگو یا ابزارهای متصل ChatGPT دسترسی نمی‌دهد.

برای اجرای مستقل ابزار کدنویس GitHub:

```powershell
.\windows\Start-AminChatGPTGitHubAgent.ps1 -Repo "OWNER/REPOSITORY"
```

نام مخزن **ثابت و تأییدشده** است. اسکریپت توکن GitHub محدود به همان مخزن و شرح کار را می‌گیرد و برای **ویرایش فایل‌ها و PR پیش‌نویس**، تأیید جداگانه می‌خواهد. اگر مخزن عمومی است، اجازهٔ جداگانهٔ انتشار کد را نیز می‌خواهد. توکن از این اسکریپت به مدل یا GitHub عمومی ارسال نمی‌شود. این توکن فقط برای GitHub REST است؛ OpenAI درخواست‌های مدل را با OAuth مجاز کاربر پردازش می‌کند.

اجازهٔ پیشنهادی توکن GitHub: `Contents: Read and write`، `Pull requests: Read and write`، `Actions: Read` در همان مخزن. برای فقط تحلیل، `Contents: Read` کافی است. هیچ مجوز Admin، Secrets، Actions:write، و اجرای دستورات سیستم لازم نیست.

## راه‌اندازی از گوشی و ویندوز با تونل WSS

این مرحله **برای اجرای روی رایانهٔ مالک** است؛ نه یک سرور میزبانی‌شده که سهمیهٔ Plus مالک را به کاربران بفروشد. پس از احراز هویت ChatGPT، محیط مالک می‌تواند برای برنامهٔ خاصی مخزن تعیین کند:

```powershell
$env:AMIN_SIWC_ENABLE = "1"
$env:AMIN_SIWC_AGENT_ENABLE = "1"
$env:AMIN_LIVE_OWNER_TOKEN_ID = "<owner-scoped-token-id>"
$env:AMIN_AGENT_PROJECT_REPOS_JSON = '{"support":"OWNER/REPOSITORY"}'
$env:AMIN_AGENT_ALLOW_PUBLIC = "1"   # ONLY if repo is public AND explicitly approved
$env:AMIN_AGENT_GITHUB_TOKEN = "<repo-scoped GitHub credential>"
python live_bridge.py --host 127.0.0.1 --port 8766
```

**مهم:** `AMIN_LIVE_OWNER_TOKEN_ID` خودِ کلید ورود نیست؛ شناسهٔ توکن اختصاصی مالک است که قبلاً از طریق صدور دسترسی موتور ساخته می‌شود. آدرس شبکه و TLS گواهی معتبر برای استفادهٔ گوشی از بیرون رایانه هنوز باید روی دستگاه واقعی تنظیم شود.

برای هر `project` مجاز، یک مخزن در `AMIN_AGENT_PROJECT_REPOS_JSON` تعریف می‌شود. این نگاشت *با درخواست مدل قابل تغییر نیست*. برنامهٔ اندروید یا وب **مقصد و نوع کار** و **اجازهٔ جداگانهٔ اصلاح GitHub** را همراه درخواست می‌فرستند. پاسخ با `job_id` یکتا برمی‌گردد. اگر شبکه قطع شد، وضعیت و نتیجهٔ مشاهده‌شده در SQLite باقی می‌ماند و از طریق `resume` دریافت می‌شود. ارسال مجدد همان `request_key` نباید کار دوم بسازد. سهمیهٔ ChatGPT مالک به حساب کاربران دیگر انتقال نمی‌یابد.

## قیود امنیت و عملیاتی

- ادغام در `main`، نصب APK، اجرای فرمان PowerShell، انتشار نسخه، تغییر workflowهای CI، Secrets و عملیات حساب معاملاتی **غیرمجاز** هستند.
- اندازهٔ فایل نوشتنی در نسخهٔ فعلی برای هر بار نوشتن **۸۵۰۰ بایت** است؛ حداکثر ۱۲ نوشتن و ۳۰ عملیات GitHub در هر درخواست. این محدودیت جهت جلوگیری از ارسال کد ناقص یا عملیات نامحدود است؛ برای فایل‌های بزرگ‌تر، روش patch ایمن باید جداگانه پیاده‌سازی شود.
- مسیر مدل فقط ابزار function/custom محلی دارد. ابزارهای **داخلی همین گفت‌وگوی ChatGPT**، hosted MCP، File Search، Code Interpreter و اجرای کد روی سیستم مقصد در مسیر OAuth SIWC منتقل نمی‌شوند. <https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations>
- اگر ورود ChatGPT، مدل انتخابی، سهمیه، شبکه یا GitHub اجازه ندهد، پاسخ **Blocked/Failed** است؛ استفادهٔ خودکار از API پولی یا Codex وجود ندارد.
- اتصال رسمی برای **نرم‌افزار متن‌باز و self-hosted** توصیف شده است. ارائهٔ سرویس تجاری میزبانی‌شده یا استفاده از سهمیهٔ یک نفر برای مشتریان، به بررسی شرایط OpenAI و مجوز جداگانه نیاز دارد.
- آزمون‌های خودکار فعلی از مدل و GitHub **ساختگی کنترل‌شده** استفاده می‌کنند تا منطق بررسی شود؛ خروجی آن‌ها `simulation:true` و `model_used:false` است. این نتایج **به‌جای ورود واقعی ChatGPT، تغییر کد واقعی توسط مدل، نصب روی گوشی و کارکرد شبکه ایران پذیرفته نمی‌شوند**.

## معیار پذیرش نهایی

۱. ورود واقعی ChatGPT صاحب حساب با OAuth و بدون کلید API پولی و ارسال یک درخواست واقعی مدل.

۲. درخواست از Galaxy M62 یا ویندوز برسد، مدل مجاز با ابزارها یک تغییر واقعی **فقط در شاخهٔ جدا** بسازد و PR پیش‌نویس ایجاد کند؛ لینک و CI همان تغییر در دستگاه دیده شود.

۳. آزمون CI روی شاخهٔ واقعی و تأیید شخصی مالک؛ نصب یا اجرای خروجی روی دستگاه با اجازهٔ جداگانه و آزمایش کارکرد. تا این سه مورد انجام نشود، **موتور کامل اعلام نمی‌شود**.

# تشخیص خطای «برنامه نصب نشد» در Galaxy M62
تاریخ: ۲۲ نوامبر ۲۰۲۶. تصویر کاربر پیام عمومی نصب را نشان می‌دهد؛ هیچ کد خطای PackageManager در تصویر نیست.

## نتیجه بررسی واقعی APK
- آخرین debug APK: `com.amin.support.mobile.compat`، نسخه ۲، حداقل API ۲۶، هدف API ۳۳.
- ZIP را از فایل واقعی بررسی کردیم: تمام ورودی‌ها سالم، APK Signature Scheme v2 در فایل موجود است.
- **ایراد تأییدشده در روند انتشار:** امضای دیجیتال به‌وسیلهٔ keystore موقت GitHub Actions ساخته می‌شود. دو خروجی مجزا دارای گواهی‌های متفاوت‌اند؛ خروجی debug جدید را نمی‌توان روی برنامهٔ نصب‌شده با همان package ID و گواهی قبلی به‌صورت update نصب کرد.
- گواهی نمونه خروجی سازگار: `dad3dea99bb3e8b565cea304be126131e3832476e7bb041a4685b2adb4e4bac2`
- گواهی نمونه فایل دیگری با همان نسخه: `e6b7f18840bb742983781c7bb85cd5603a1f4d60e9d51d41871c2b745efbaf8a`
- هش SHA-256 فایل سازگار: `1e193ca835332ca8acdbefc9378bba16fa2b28cab90459fd373be0700a5c11a3`
- **علت قطعی خطای گوشی هنوز تشخیص داده نشده است:** اگر آن package ID روی گوشی موجود نبوده، تعارض امضا توضیح کافی نیست. نصب موفق یا ناموفق در شبیه‌ساز فقط آزمون شبیه‌ساز است.

## آزمون مستقل
CI جدید علاوه بر build، اعتبار امضای v2، هم‌ترازی ZIP و تطبیق manifest را با ابزار رسمی Android SDK کنترل می‌کند. گردش‌کار دوم تلاش به نصب و اجرای APK در شبیه‌ساز اندروید ۱۳ می‌کند. موفقیت شبیه‌ساز به معنی نصب موفق روی Galaxy M62 نیست.

## تشخیص روی گوشی بدون حذف برنامه‌های قبلی
برای یافتن *علت واقعی*، ابتدا دستگاه را با USB Debugging به ویندوز متصل کنید؛ سپس با نسخه رسمی Android Platform Tools:
```powershell
adb devices
adb install -r "C:\PATH\TO\Amin-AI-Android-Compat-Latest-2026-11-22.apk"
```
خروجی ممکن است `INSTALL_FAILED_UPDATE_INCOMPATIBLE`، `INSTALL_FAILED_CONFLICTING_PROVIDER`، `INSTALL_FAILED_NO_MATCHING_ABIS`، `INSTALL_FAILED_VERIFICATION_FAILURE` و ... باشد. فقط نتیجهٔ واقعی را مبنای اصلاح قرار دهید. **هیچ برنامه‌ای را حذف نکنید** و برای تشخیص، Play Protect یا تنظیمات حفاظتی را کورکورانه خاموش نکنید.

## راه پایدار انتشار (هنوز نیازمند تنظیم واقعی)
برای هر نسخهٔ قابل‌نصب و به‌روزرسانی، یک کلید خصوصی ثابتِ متعلق به مالک باید ایجاد و در فضای محرمانه و دارای نسخه پشتیبان نگهداری شود؛ سپس تمام خروجی‌های عمومی با همان کلید sign شوند. کلید خصوصی را هرگز داخل مخزن عمومی یا فایل APK قرار ندهید. GitHub Actions debug keystore یک کلید ثابت و تجاری نیست. در نبود کلید، تنها خروجی آزمایشی است و ادعای حلِ دائمی نصب نادرست است.

# کانال زنده و دوطرفه هوش امین — Android / Windows / Web

## ۱. درخواست مالک و تفاوت سه لایه

کانال **WebSocket امن (WSS)** یک اتصال زنده و دوسویه برای متن است. کلاینت می‌تواند در یک اتصال چند پرسش هم‌زمان بفرستد، پیام `accepted`، `answer`، `progress` و `work_state` دریافت کند و بدون قطع ارتباط سؤال جدید بپرسد. هنگام قطع اینترنت، شناسهٔ کار در SQLite باقی می‌ماند و با `resume` بازیابی می‌شود. هیچ بررسی **ساعتی** برای این کانال لازم نیست.

- **مکالمه نوشتاری:** در اپ اندروید، صفحه وب ویندوز، و خط فرمان ویندوز کدنویسی شده است.
- **مکالمه صوتی:** در اندروید دکمه گفتار فارسی → متن و TextToSpeech فارسی اضافه شده؛ در وب قابلیت گفتار مرورگر از قبل وجود دارد. استفاده از موتور گفتار سیستم ممکن است به سرویس خارجی وابسته باشد و محرمانگی/دسترس‌پذیری آن باید روی دستگاه بررسی شود. **صوت پیوسته هم‌زمان مثل تماس تلفنی، قطع گفتار (barge-in)، استریم صوت WebRTC و پردازش پیوسته میکروفون هنوز ساخته نشده است.** فعلاً ورودی گفتار نوبتی است، اما کانال متن می‌تواند هم‌زمان چند کار را پردازش کند.
- **اثرگذاری محیط بیرونی:** کاربر نوع کار و مقصد `android|windows|web|github|none` را انتخاب می‌کند. درخواست `build|repair|analyze|release|answer` به صف خصوصی GitHub می‌رود، ولی **صرف ارسال کار اجرای برنامه نیست**. اجرای خودکار تغییر فایل یا انتشار عمومی به عامل اجرای معتبر با مجوز و آزمون نیاز دارد. انتشار فایل نرم‌افزار پس از ساخت نیز مستقل از مرحله کار است.

## ۲. پروتکل

ابتدا WebSocket به آدرس `wss://<trusted-host>:8766/` وصل می‌شود. برای آزمایش روی **همان ویندوز** فقط `ws://127.0.0.1:8766` مجاز است. توکن در اولین فریم `auth` ارسال می‌شود، **نه در URL یا GitHub عمومی**. کلید `amin_...` باید برای همان نرم‌افزار صادر شده باشد.

```json
{"type":"auth","token":"<client-scoped-secret>"}
{"type":"ask","id":"a1","project":"support","message":"مشکل برنامه چیست؟"}
{"type":"work","id":"a2","project":"support","message":"اپ ثبت سفارش برای گوشی بساز","consent":true,"target_environment":"android","requested_operation":"build"}
{"type":"resume","id":"a3","project":"support","job_id":"<32hex>"}
```

پاسخ `ready` مشخص می‌کند اتصال زنده برقرار است ولی `personal_chatgpt_connected=false` است، چون **این کد به گفت‌وگوی ChatGPT یک فرد دسترسی خودکار ندارد**. `work_state` شناسهٔ `id_of_job`، مرحله واقعی و ناتمام بودن اجرا را مشخص می‌کند. این پیام هم‌زمان با درخواست‌های دیگر روی کانال می‌آید. هر درخواست به project و کلید مشتری محدود شده و rate limit دارد.

## ۳. بازگرداندن برنامه ساخته‌شده به محیط انتخابی

پاسخ مجاز **مالک مخزن خصوصی** یا GitHub Actions bot می‌تواند به‌جای ادعای نصب، نشانی انتشار نسخه و SHA-256 را در بخش زیر ارائه دهد:

```json
{"request_id":"<32hex>","status":"answered","answer":"خروجی ساخته‌شده؛ شواهد تست پیوست است","needs_human":false,"action_performed":false,"artifact":{"environment":"android","url":"https://github.com/OWNER/REPO/releases/download/v1/app.apk","sha256":"<64 hex SHA-256>"}}
```

لینک و SHA صرفاً وقتی از **Comment در مخزن خصوصی مجاز** خوانده شوند و معیارهای امن را بگذرانند، وارد کلاینت می‌شوند. اینها به‌تنهایی اثبات اصالت منتشرکننده نیستند. برای اندروید، دانلود APK از `github.com` با انتقال TLS مجاز و کنترل SHA-256 انجام می‌شود و بعد با **دو مجوز روشن کاربر** نصب‌کننده رسمی Android باز می‌شود؛ هیچ برنامه‌ای خودکار نصب نمی‌شود. برای ویندوز، فایل ZIP/MSI/MSIX/EXE به پوشه مشخص کاربر منتقل و SHA-256 بررسی می‌شود؛ **فایل هرگز خودکار اجرا یا نصب نمی‌شود**. در مرورگر فقط لینک انتشار نمایش داده می‌شود. تا وقتی فایل واقعاً روی دستگاه دریافت و نصب نشده، وضعیت `installed=false` است.

## ۴. محیط نصب

روی رایانه‌ای که موتور اصلی روی آن قرار دارد (ویندوز یا سرور تحت کنترل مالک)، با Python 3.11 و کتابخانه آزاد websockets:

```powershell
python -m pip install "websockets>=14,<18"
cd amin-ai-support
python amin_support.py issue-access --project support --allow-ticket
$env:AMIN_LIVE_OWNER_TOKEN_ID = "<token_id output from issue-access>"
$env:AMIN_LIVE_GITHUB_REPO = "OWNER/PRIVATE_REPO"
$env:AMIN_LIVE_GITHUB_TOKEN = "<repo-scoped GitHub token; owner only>"
python live_bridge.py --host 127.0.0.1 --port 8766
```

`issue-access` نیازمند پروژه از پیش ثبت‌شده است؛ دستور بالا برای پروژهٔ `support` فقط بعد از ثبت پروژه معتبر است. توکن و کلید در مخزن یا APK قرار نمی‌گیرند. برای موبایل از راه دور، باید میزبان دائماً روشن و آدرس شبکه قابل دسترس و گواهی TLS معتبر روی WSS تنظیم باشد. **در صورت نداشتن سرور/میزبان روشن، این کانال WSS از بیرون در دسترس نیست**؛ حالت مستقیم GitHub خصوصی به‌عنوان راه جایگزین وجود دارد، اما تأخیر و محدودیت‌های GitHub را دارد.

برای ویندوز:
```powershell
.\windows\Start-AminLiveClient.ps1 -Url "ws://127.0.0.1:8766"
```

در دستور خط فرمان: `ask <question>`، `work windows build <request>`، `resume <jobid>`، `deliver` بعد از مشاهده نسخه منتشرشده و مجوز جداگانه.

## ۵. حریم خصوصی و دسترسی چندنفره

- همان کد عمومی می‌تواند برای نرم‌افزارهای مختلف استفاده شود، ولی حافظه و دسترسی مشتریان باید جدا باشند.
- **توکن GitHub خصوصی که روی میزبان قرار می‌گیرد فقط برای کلید مالک** با `AMIN_LIVE_OWNER_TOKEN_ID` کاربرد دارد؛ درخواست دیگر مشتریان هرگز با این کلید به مخزن مالک منتشر نمی‌شود. هر کاربر دیگر باید پل GitHub خصوصی خودش را از طریق اپ مستقیم به‌طور مستقل فعال کند. پیاده‌سازی کامل هویت انسانی چنددستگاهی و جفت‌کردن حساب‌ها ناتمام است.
- درخواست خام از کاربران را به‌عنوان دستور امنیتی/اجباری برای اجرا در runner یا سیستم میزبان تفسیر نکنید. اجرا نیازمند ابزار/agent دارای مجوز، branch/PR و آزمون است.
- اتصال ChatGPT با جریان WebSocket صرفاً با داشتن اشتراک ChatGPT فعال نمی‌شود؛ API یا گردش‌کار رویدادمحور مورد پشتیبانی و مجوزهای آن لازم است. OpenAI API ممکن است هزینه داشته باشد؛ این نسخه برای شما هیچ خرید یا پرداخت جدیدی آغاز نمی‌کند.

## ۶. وضعیت آزمون و مانع

آزمون‌های واحد و یکپارچه در CI، اجرای WebSocket loopback، build اندروید و جداسازی کارها باید قبل از تأیید نصب بررسی شوند. این آزمون‌ها **قبولی روی Galaxy M62، کیفیت صوت فارسی، دسترس‌پذیری شبکه ایران، اتصال خودکار به همین حساب ChatGPT، ساخت خودکار هر نوع نرم‌افزار یا نصب واقعاً موفق روی دستگاه شما** نیستند.

**معیار قبولی نهایی مالک:** گفتگوی صوتی/متنی مؤثر، اجرای درخواست در مخزن توسط عامل مجاز، ساخت و تست واقعی، دانلود و نصب تحت کنترل کاربر و دریافت بازخورد و یادگیری تدریجی با تأیید. تا رسیدن به همهٔ این مراحل پروژه تکمیل‌شده معرفی نشود.


## اصلاحات امنیتی و آزمون شبکه «برنامه جواب» — ۲۲ نوامبر ۲۰۲۶

- فایل `projects.json` اکنون پروژهٔ `support` را با مسیرهای محدودِ مستندات عمومی ثبت می‌کند؛ صدور کلید مخصوص آن قابل اجراست. مجوز دسترسی به پروژه‌های دیگر منتقل نمی‌شود.
- اپ اندروید برای WSS از **کلید مستقل AndroidKeyStore** با نام `LiveTokenVault` استفاده می‌کند که به همان آدرس `wss://host:port` وابسته است. تغییر سرور با کلید ذخیره‌شده اتصال خودکار برقرار نمی‌کند؛ ورود دوبارهٔ کلید لازم است. کلید تنها بعد از پاسخ احراز هویت درست ذخیره می‌شود.
- کلاینت WSS اندروید انتقال خودکار به نشانی دیگر را غیرفعال می‌کند و قبل از ارسال فریم کلید، نام میزبان و پورت TLS را با مقصد اولیه تطبیق می‌دهد.
- سرور WSS فقط Originهای وبِ مورد تأیید را قبول می‌کند؛ برنامه‌های بومی اندروید/ویندوز Origin مرورگر ندارند. در رایانهٔ محلی دو نشانی `http://localhost:8765` و `http://127.0.0.1:8765` مجازند. برای وب‌سایت عمومی، **مبدأ دقیق HTTPS** را با `--allowed-origin https://your.site` هنگام اجرای `live_bridge.py` یا `AMIN_LIVE_ALLOWED_ORIGINS` تنظیم کنید. هیچ Origin عمومی یا wildcard به‌صورت پیش‌فرض پذیرفته نمی‌شود.
- دکمهٔ «آزمایش اتصال GitHub و TLS کانال زنده بدون ارسال رمز» در اپ اندروید اضافه شد. این دکمه فقط دسترسی عمومی `api.github.com` و handshake گواهی TLS مقصد را از **خود دستگاه** بررسی می‌کند. هیچ توکن، سؤال یا شناسه کاربر ارسال نمی‌شود. نتیجهٔ GitHub 403 نیز نشان‌دهندهٔ دسترسی به سرور است، نه اجازه کار با حساب GitHub.
- آزمایش TLS مستقیم لزوماً عملکرد مسیر VPN/Proxy یا دسترسی به ChatGPT را تضمین نمی‌کند؛ اگر شبکه ایران فقط مسیر واسط خاصی را باز کند، این آزمایش ممکن است شکست بخورد در حالی که مسیر دیگری کار کند. معیار اصلی، آزمون واقعی اپ روی شبکه مقصد و پاسخ قابل پیگیری است.
- CI تنها آزمون روی runner است. **نصب و آزمون شبکه و مکالمهٔ فارسی روی Galaxy M62، راه‌اندازی میزبان زنده در ویندوز مالک و دسترسی لحظه‌ای به خود حساب ChatGPT هنوز انجام نشده‌اند.** استقرار عمومی تا تأیید مالک ممنوع است.

# کانال اختصاصی هوش امین: گوشی ⇄ موتور مشترک ⇄ GitHub خصوصی ⇄ عامل مجاز ⇄ دستگاه درخواست‌دهنده

## وضعیت این نسخه
این نسخه **زیرساخت ارجاع خصوصی و برگشت پاسخ** را کدنویسی می‌کند؛ «تونل خودکار به چت شخصی ChatGPT» هنوز وجود ندارد. مخزن `amin-faraz` می‌تواند عمومی بماند، اما داده شخصی مشتریان نباید به Issue / Actions / Artifact / Commit / Log آن نوشته شود.

### مسیر واقعی موجود
1. اپ اندروید یا صفحه ویندوز از طریق HTTPS معتبر و `Bearer amin_...` با موتور مشترک گفتگو می‌کند.
2. در صورت ناتوانی موتور، کاربر با رضایت مشخص `POST /api/handoff` را می‌زند. برنامه می‌تواند با تیک انتخابی و فقط هنگام `needs_human=true` نیز ارجاع دهد. متن کامل فقط در SQLite **خصوصیِ محل نصب موتور** ثبت می‌شود.
3. هر ارجاع شناسه تصادفی `id` دارد. فقط سرور و کلید همان مشتری/نرم‌افزار می‌توانند آن را بخوانند.
4. در صورت تنظیم اختیاری متغیرهای `AMIN_HANDOFF_GITHUB_TOKEN` و `AMIN_HANDOFF_GITHUB_REPO`، سرور ابتدا با API GitHub **خصوصی بودن مخزن مقصد را تأیید** می‌کند. اگر مقصد عمومی باشد، هیچ Issue ساخته نمی‌شود. اگر خصوصی باشد، فقط شناسه تصادفی و عبارت قراردادی بدون متن یا محتوای شخصی در آن مخزن قرار می‌گیرد.
5. اپ از `GET /api/handoff?id=...` وضعیت را بررسی می‌کند. درخواست مخفی کاربران دیگر حتی با داشتن شناسه، به دلیل جداسازی کلید غیرقابل بازیابی است.
6. اپراتور یا عامل **مجاز** باید متن را از محیط خصوصی با `handoff-pending` بخواند، بررسی کند و پاسخ را با `handoff-answer` برگرداند. اجرای خودکار ChatGPT، اتصال به حساب جداگانه هر شخص، یا اجرای Codex به صرف ثبت Issue **انجام نشده است**.
7. پاسخ از پایگاه‌دادهٔ خصوصی به همان مشتری برمی‌گردد. پاسخ تا زمانی که مدیر نرم‌افزار جداگانه تأیید نکرده، به «درس مشترک» تبدیل نمی‌شود.

### API
```text
POST /api/handoff
Authorization: Bearer <one client/program scoped token>
{"project":"alpha","message":"متن مشکل","consent":true}

201 {"id":"32hex","project":"alpha","status":"pending",
     "github_state":"not_configured|published|failed",
     "chatgpt_invoked":false,"public_text_uploaded":false}

GET /api/handoff?id=<32hex>
Authorization: Bearer <same token>

200 {"status":"pending|answered","answer":"..."}
```
در حالت `allow_ticket=false`، ارجاع رد می‌شود. سهمیه همان سهمیه تیکت است و متن بدون رضایت صریح ذخیره نمی‌شود. اتمام اعتبار ممکن است 402 برگرداند. شناسه عمومی در مخزن کد قرار نمی‌گیرد.

### اجرای اپراتور محلی (مثال بدون اطلاعات واقعی)
```text
python amin_support.py handoff-pending --project alpha
python amin_support.py handoff-answer --project alpha --id <32hex> --answer "راه‌حل بررسی‌شده"
```
این فرمان‌ها فقط باید روی رایانه/سرور امن مالک با دسترسی به پایگاه داده اجرا شوند، نه از گوشی مشتری. ارسال پاسخ و تغییر نرم‌افزار دو عملیات جداگانه‌اند؛ این نسخه امکان اجرای خودکار کد و استقرار روی دستگاه مردم را نمی‌دهد.

### ارتباط با ChatGPT هر کاربر
برای رساندن خودکار درخواست به **چت شخصی همان کاربر** باید هر کاربر اتصال حساب خودش را صریحاً برقرار کند و یک API / رابط مورد پشتیبانی، احراز هویت و مجوز لازم موجود باشد. یک مخزن GitHub عمومی یا خصوصی به‌تنهایی نمی‌تواند با یک گفت‌وگوی فعال ChatGPT تماس بگیرد، آن را بیدار کند یا پاسخ آن را دریافت کند. ذخیره توکن شخصی ChatGPT در کد، APK یا Issue ممنوع است. راه‌اندازی ادعایی «تونل» بدون آزمون تبادل واقعی پذیرفته نیست.

### گلوگاه‌های باقی‌مانده
- موتور باید روی یک دستگاه امن و قابل‌دسترسی روشن باشد؛ دسترسی HTTPS از شبکه‌های ایران هنوز آزمایش نشده.
- کلیدهای فعلی «نرم‌افزار-محدود» هستند، نه ورود حساب انسانی. برای محصول تجاری به هویت فردی، جفت‌کردن دستگاه‌ها، لغو نشست، مالکیت کاربر و پشتیبانی چند دستگاه نیاز است. به هر مشتری کلید جداگانه بدهید؛ **یک کلید مشترک برای همه مشتریان صادر نکنید**.
- ساخت و اجرای مستقل مدل روی اندروید، پل واقعی خودکار GitHub⇄ChatGPT/Codex، یادگیری مبتنی بر بازخورد با سنجش کیفیت، صف مقاوم در برابر خاموشی سرور، رمزگذاری داده در حالت سکون و آزمون روی گوشی واقعی ناتمام‌اند.
- در حالت نبود اتصال GitHub، داده در SQLite خصوصی ثبت می‌شود و ارجاع نه گم شده فرض می‌شود، نه انجام شده؛ `github_state=not_configured` یا `failed` نمایش داده می‌شود.
- هیچ API پولی و هیچ پرداخت جدید برای این تغییر لازم نیست. هزینه برق/اینترنت/زمان اجرا صفر واقعی تضمین نمی‌شود.

**معیار قبولی:** نصب و آزمون مسیر کامل گوشی/ویندوز تا پاسخ، جداسازی اطلاعات حساب‌های واقعی، جلوگیری از نشت مخزن عمومی، ساخت APK جدید، دسترسی HTTPS روی اینترنت هدف و تشخیص دقیق «پاسخ مستند» از «عملیات انجام‌شده». موفقیت Unit Test یا CI قبولی محصول نیست.
